q4) Transition counts are stored in the model's self.transition_counts
dictionary. Each previous token is a key, and its value is a Counter that
stores counts for each following token. For example, the entry for "the"
contains counts for "cat", "dog", "mat", "rug", and "park".

q5) P(next token | previous token) is computed in __init__ when the model
builds self.probabilities. For each pair, it divides that pair's count by the
total count of all transitions starting with the previous token:

P(next | previous) = count(previous, next) / total_outgoing_count(previous)

q6) The program has both behaviors, in different methods. predict_next()
chooses the most probable next token (breaking ties alphabetically). In
generate_sentence(), random.choices() samples a next token using the learned
probabilities as weights. Choosing the most probable token always returns the
same choice for a given context; sampling can choose less probable tokens too,
so generated sentences can vary like some sort of temperature measure or top p in llms.

q7) If a token has no observed outgoing transitions, distribution() raises a
ValueError saying there are no outgoing transitions for that token. The model
does not smooth the probabilities or back off to another context. During
generation, <END> stops generation before the model needs a distribution for
it.

q8) A total of 0.87 means the conditional probabilities for that current word
do not form a complete probability distribution: 0.13 of the probability mass
is missing. The total should be approximately 1. This suggests checking the
transition counts, the denominator used to normalize them, and whether every
observed next-token transition is included. Small floating-point differences
are normal, but 0.87 is too far from 1 to be rounding error.

q9) Not always. The model chooses next words from frequencies in its small
training dataset, using only the immediately preceding word. It does not use
the full sentence meaning or broader linguistic knowledge also in this, the next word is dependent only on the previous 
word so sentences wont be necessarily coherent because normally our sentences have longer term 
dependencies

For this dataset, the five contexts give:
  the -> cat (0.25) or dog (0.25), a tie; the program returns cat because its
         tie-breaking rule chooses alphabetically
  cat -> sat (2/3)
  dog -> sat (2/3)
  sat -> on (1)
  ran -> to (1)

This illustrates the difference between a probability model, which reports
patterns and frequencies learned from its training data, and human linguistic
expectations, which can use meaning, context, and knowledge beyond that data.
